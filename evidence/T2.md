## Implementation choices

`lib/nav.ts` is the single primary-navigation model. Its labels are exactly
`Start`, `Use Store`, `Integrations`, `Test`, `Reference`, and `Project`; the
Reference destination is `/reference/store6-core/index.html`. It partitions
the existing Fumadocs page tree into Store5 and Store6 siblings. Pages under
`/docs/store6` belong to Store6 and the remaining current tree belongs to
Store5.

The shell uses the paper semantic background, the verified AppLayout compound,
the shared Fumadocs tree, a FloatingToc right rail, semantic status text, and

numbered token utilities.

### Recursive navigation and TOC state

`SideTree` recursively retains the Fumadocs folder hierarchy. Folder rows use
their index page as `href`, render icons, show descriptions as secondary text,
and expose a separate `MenuTrigger`. Stable keys prefer the PageTree `$id`,
folder reference, or index URL before a structural fallback. The installed
React Aria Tree contract accepts `expandedKeys?: Iterable<Key>` and
`onExpandedChange?: (keys: Set<Key>) => any`, where `Key` is `string | number`.
`SideTree` derives that callback type from `SidebarMenuProps` and uses a
controlled expansion set without a cast.

The initial set includes `defaultOpen` folders, current-page ancestors, and all
non-collapsible folder IDs. Each proposed React Aria set is normalized by
re-adding every non-collapsible ID. Normal folders otherwise follow the
proposed set, so they remain user-collapsible. Navigation merges current-page
ancestors and newly introduced `defaultOpen` IDs into the existing state. It
does not reopen a previously seen folder solely because `defaultOpen` remains
true, or reset unrelated user choices. A non-collapsible folder's
`MenuTrigger` remains disabled. A page is current only when its URL exactly
matches the current path. A folder is current only when its own index URL
matches; descendant containment expands ancestors without marking them
current.

HeroUI's React Aria Tree rejects a raw separator as a direct tree row. Each
PageTree separator is therefore a disabled `Sidebar.MenuItem` whose content
includes the verified `Sidebar.Separator`; its optional icon and name remain
available in the row.

A temporary static fixture exercised folder → nested folder → page and a named
separator without adding a permanent route. Before the correction, the two
pages were flattened at `aria-level="1"` and no Sidebar separator rendered.
After the correction, the outer folder rendered expanded at level `1`, the
separator and nested folder at level `2`, and the current leaf at level `3`.
The folder index href, disabled non-collapsible trigger, and both descriptions
were present. A second temporary nested fixture found exactly one current row:
`{"currentItems":1,"labels":["Nested leaf"],"levels":["3"]}`. Both ancestor
folders remained expanded without receiving current state. Neither fixture
route remains in the application. T4's nested migrated content remains the
later full content-tree render exercise.

`ActiveFloatingToc` starts closed with no active item in server-rendered HTML.
The root uses controlled `open` and `onOpenChange`. Its Trigger exposes the
truthful expanded state, a changing Open/Close accessible name, and
`aria-controls` for a stable `useId` value. The installed Content type does not
accept a direct `id`, so its immediate content region owns the matching ID
without a cast. After hydration, native hash changes select their matching
heading and an `IntersectionObserver` follows the heading at the reading line.
Active links receive `aria-current="location"`; navigation remains an href and
application source contains no `onClick`. Closed Popover content is not emitted
in initial HTML, so the matching content ID is established by source inspection
and the successful typechecked build rather than a claim about initial static
markup.

### CodeSlab decision

The custom Shiki implementation was selected over the Pro CodeBlock subpath.
Both approaches satisfy syntax highlighting and copy affordances, but the
custom server-side renderer applies the required Store code surface and
foreground tokens directly and maps syntax scopes to all four provisional
origin on-dark tokens. A narrow client-only base Button owns clipboard state
and uses `onPress`; the highlighted code remains server-rendered. The copy
control detects a missing Clipboard API and catches rejected writes. Its stable
button name avoids duplicating the separate polite success or failure
announcement, while its visible label reports `Copy`, `Copied`, or
`Copy failed`. Attempt guards and cleaned-up announcement/reset timers prevent
stale results after a later press or unmount.

A direct Shiki fixture assertion exited `0` and found the Store code foreground,
all four origin on-dark variables, and the `shiki store-code` class in the
generated markup. An earlier diagnostic exited `1` because it expected the
outer surface variable inside Shiki markup despite `rootStyle: false`, and its
fixture contained no string token while expecting the source-of-truth string
color. The corrected fixture covers comments, keywords, function calls, and
strings; the outer `CodeSlab` owns the surface token as intended.
