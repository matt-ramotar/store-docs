## Implementation choices

`lib/nav.ts` is the single primary-navigation model. Its labels are exactly
`Start`, `Use Store`, `Integrations`, `Test`, `Reference`, and `Project`; the
Reference destination is `/reference/store6-core/index.html`. It partitions
the existing Fumadocs page tree into Store5 and Store6 siblings. Pages under
`/docs/store6` belong to Store6 and the remaining current tree belongs to
Store5.

The shell uses the paper semantic background, the verified AppLayout compound,
the shared Fumadocs tree, a FloatingToc right rail, semantic status text, and
Separator hairlines. It does not add a HeroUI provider, nested card framing, or
numbered token utilities.

### CodeSlab decision

The custom Shiki implementation was selected over the Pro CodeBlock subpath.
Both approaches satisfy syntax highlighting and copy affordances, but the
custom server-side renderer applies the required Store code surface and
foreground tokens directly and maps syntax scopes to all four provisional
origin on-dark tokens. A narrow client-only base Button owns clipboard state
and uses `onPress`; the highlighted code remains server-rendered.

A direct Shiki fixture assertion exited `0` and found the Store code foreground,
all four origin on-dark variables, and the `shiki store-code` class in the
generated markup. An earlier diagnostic exited `1` because it expected the
outer surface variable inside Shiki markup despite `rootStyle: false`, and its
fixture contained no string token while expecting the source-of-truth string
color. The corrected fixture covers comments, keywords, function calls, and
strings; the outer `CodeSlab` owns the surface token as intended.
