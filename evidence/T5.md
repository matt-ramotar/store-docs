## Local-index deviation

The plan describes `@orama/core` as a local indexing peer. The installed
`@orama/core@1.2.19` package does not expose the local `create`, `insert`,
`save`, `load`, and `search` API required by that design. Its package metadata
describes it as an OramaCore client. Its installed `CollectionManager`
requires a collection ID and API key, defaults its reader endpoint to
`https://collections.orama.com`, and sends searches to a collection endpoint.
Its manager creates remote collections through a configured writer endpoint.
Using that package literally would require credentials and outward requests,
which are outside this run's boundary.

The completed implementation therefore uses Fumadocs 16.12.1's supported
public local-search APIs:

- `createFromSource(source)` from `fumadocs-core/search/server` builds both
  documentation trees from the shared loader;
- `searchIndex.staticGET()` is exported from the force-static
  `/api/search` route;
- `oramaStaticClient({ from: "/api/search" })` and `useDocsSearch` load and
  query that artifact in the client island.

Application source does not import `@orama/orama` directly. Fumadocs owns its
internal local-engine integration. `@orama/core` remains installed at the
plan-pinned resolved version, but no cloud client, collection identifier, API
key, or outward search URL appears in the T5 implementation. This is
Done-with-deviation, not a blocked outcome, because the local indexing and
palette implementation and its mechanical query gate are available without an
outward write.

## HeroUI contract

The live unified HeroUI MCP inventory was read before component docs and was
refreshed for the remediation. It lists `command` under Pro navigation and
`button`, `chip`, and `kbd` under the base package. The live Command
documentation and the installed declaration files agree on the compound
structure used here: `Command`, `Backdrop`, `Container`, `Dialog`,
`InputGroup`, `List`, `Group`, `Item`, and `Footer`. The installed Dialog
declaration supports controlled `inputValue`, `onInputChange`, and a
caller-supplied `filter`. The base Button documentation specifies `onPress`;
the Chip documentation specifies `Chip.Label`.

`CommandSearch` uses a controlled backdrop and input, `filter={() => true}` so
the local engine remains the result authority, an autofocused labeled input,
a labeled result list, and caller-owned selection and close behavior. A
request-generation tracker associates each returned array or error with the
normalized input generation that started it. Blank input, a changed query, a
pending request, an error, and a late prior-generation response all expose an
empty actionable result set. Selection resolves only against that set. With
`delayMs: 0`, each distinct non-empty input value starts its own tracked local
request instead of leaving a debounce interval in which a returned prior
generation could be mistaken for the current one.

The tracker normalizes a returned `SortedResult[]` once and caches the
normalized array by raw-array identity and input generation. Repeated ready
renders and action lookup use that same array and its result objects. A new raw
array receives a new normalization, and reusing one raw-array object for a new
generation replaces the prior cached value. The generation check continues to
disarm prior-query data.

The trigger has a stable accessible name, truthful expanded state, and a
dialog relationship only while the dialog is open. The built closed-page HTML
contains `aria-expanded="false"` and no `aria-controls`. Installed Button
source and generated HTML show that `aria-keyshortcuts` is omitted from the
server-rendered trigger even though its TypeScript surface accepts the prop.
The callback-ref source calls `setAttribute` when it receives the rendered
button. The hydrated Browser gate confirmed the closed trigger exposes
`aria-keyshortcuts="Meta+K Control+K"`, `aria-expanded="false"`, and no
`aria-controls`; opening the palette changes the expanded value to `true` and
sets `aria-controls="documentation-command-search"` while that target exists.
The global shortcut listener ignores repeated, Alt/Shift-modified, and
editable-target events and removes itself on cleanup.

Every accepted result ID is derived from its validated stable Fumadocs
`result.id`, not its result rank, and is encoded with a `search-result-` prefix
instead of using the destination URL as the item ID. Identical parsed
destination URLs are consolidated. Selection within a destination group is
deterministic by result type, readable-title length, title, context, and source
ID, while the first destination occurrence retains search order. Result URLs
are parsed and re-checked against the exact local `/docs` path allowlist,
including rejection after dot-segment normalization. Version classification
uses the parsed normalized pathname, including URLs whose Store 6 root carries
a query string or fragment.

Fumadocs highlights and Markdown are normalized to readable text before React
renders a label. The implementation parses Markdown and GFM with the pinned
`mdast-util-from-markdown`, `mdast-util-gfm`, and
`micromark-extension-gfm` packages. Input is capped at 32,768 UTF-16 code units;
parsing is caught; and the resulting AST is iteratively validated at 4,096 nodes
and depth 256 before the other tree walks. Opaque-range discovery, entity
accounting, and AST collection are iterative. A parse or resource-limit failure returns
empty text with an `invalid` residual instead of throwing.

The explicit AST collector keeps text, inline and fenced code, image alternative
text, and link children; ignores definitions; and records the handled structural
syntax kinds it consumes. A quote-, backtick-, and brace-aware iterative scanner
removes HTML/MDX tags and comments while retaining safe body text. It excludes
`script` and `style` bodies, preserves code, escaped literals, and Markdown
autolinks, and runs on each canonicalization pass so entity-created tags receive
the same handling. Escaped punctuation outside code and collected code values
use an opaque literal registry. The private-use entity fixture decodes to the
intended U+E000/U+E001 characters without aliasing that registry.

Collected text is reparsed for at most 32 passes, so syntax characters produced
by decoded entities are handled on a subsequent pass. Exhaustion returns a
`non-convergent` residual. `stripSearchMarkup` then returns empty text, and
result normalization rejects a title or breadcrumb with any residual. This
distinguishes source emphasis from an escaped literal asterisk even when both
could otherwise produce the same final characters. No HTML injection API is
used. Each result carries a visible `store5` or `store6` base Chip. Idle,
pending, empty, error, and result-count states are visible and labeled.

## Red-first record

The initial contract suite ran before production files or wiring existed. It
reported seven assertions: one passed and six failed for the missing route,
index, palette, TopNav wiring, normalizer, and built-index verifier.

Two later regressions were also captured before their fixes:

   filtered `aria-keyshortcuts`. The focused source contract then reported six

   The normalizer test reported six passing assertions and one expected
   failure until the normalized pathname received the same `/docs` allowlist
   check. The test also covers the percent-encoded dot-segment form.

The remediation suite then ran before the reviewed semantics were changed. It
reported 12 assertions: three passed and nine failed. The failures covered the
missing request-generation state machine and wiring, stale action data, stable
source identity, canonical destination deduplication, Markdown normalization,
query/fragment version classification, conditional trigger relationship, and
the expanded built-artifact verifier. After the implementation, the focused
suite reported 12 passed and zero failed.

A final action-time regression then exercised the interval after input
generation changes but before the next render replaces the selection handler.
The focused run reported one assertion and one expected failure because
`getActionableResult` did not exist. After selection moved to an action-time
tracker lookup, that focused run reported one passed and zero failed.

The label-verifier regression first ran against the output-only detector. Its
focused table reported 13 tests: seven passed and six failed. Five fixture
subtests exposed unrecognized single-marker emphasis, reference definitions,
entity-decoded emphasis, and a nested reference definition; the containing
test also failed. The expanded source-aware diagnostic fixtures then remained
red because `normalizeSearchLabel` did not exist. A separate verifier contract
failed before raw artifact labels were wired to that diagnostic. The first
source-aware regex implementation made the intermediate focused suite pass 26
tests, but adversarial review found four remaining false-pass classes: balanced
link syntax, quoted HTML attributes, entity-created code spans, and decoded
private-use characters colliding with its placeholder grammar. The expanded
table reported 19 tests: 14 passed and five failed, comprising those four
fixture failures and the containing test. A direct-parser contract also failed
before the AST imports were present. Replacing the regex normalizer with the
pinned AST parser made the complete focused suite pass 31 tests with zero
failures.

The bounded-normalization review then ran all four new contracts before their
fixes. The focused suite reported 35 tests: 31 passed and four failed. The
failures were the recursive collector's `RangeError` for a 4,007-character
deep block quote, lost visible block-HTML body text, a zero-residual depth-32
entity chain, and three normalizations of one result array across render and
action lookup. After the first implementation passed 35 tests, adversarial
extensions reported 32 passed and three failed: HTML inside code was stripped,
`stripSearchMarkup` exposed partial non-convergent text, and a raw-array object
reused for a new generation retained its prior cache. A separate source probe
also reproduced a backtick-quoted MDX attribute ending early. The final scanner,
fail-closed adapter, and generation-tagged cache resolve those cases.
A final read-only audit found that a non-HTTP CommonMark URI autolink was still
ambiguous with an XML-like tag. Preserving parser-validated angle-link ranges
made the exact URN case pass without weakening tag removal; the final audit then
returned PASS.
